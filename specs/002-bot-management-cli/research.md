# Research: Управление ботами через CLI (MVP: bot add)

**Date**: 2026-10-11 | **Status**: все NEEDS CLARIFICATION из спеки закрыты

Спека оставила плану решения: правило «4 цифр токена», число слов слага,
расположение `bots/`, предельная длина имени. Ниже — выбор и обоснование.

## R1. Скрытый ввод токена

- **Decision**: `getpass.getpass()` из stdlib.
- **Rationale**: скрывает и набор, и вставку из буфера (FR-004); POSIX и
  CI-поведение документированы (не-tty → предупреждение в stderr, чтение
  stdin); легко подменяется в тестах (monkeypatch).
- **Alternatives**: ручной termios raw-mode — дублирует getpass; сторонние
  библиотеки (prompt_toolkit) — новая зависимость без нужды.

## R2. Каркас CLI

- **Decision**: stdlib `argparse`; подкоманды `bot add` (структура
  `gram-mq bot add` уже в FR-001; будущий `bot list` встанет рядом без
  переделки).
- **Rationale**: ноль новых зависимостей (лицензионный гейт тривиально
  зелёный); нужная глубина подкоманд у argparse есть.
- **Alternatives**: click/typer — удобнее, но требуют зависимость; MVP не
  нуждается в их возможностях.

## R3. Доступ к реестру из CLI

- **Decision**: переиспользовать существующую async-инфраструктуру:
  `asyncio.run()` + `db.get_session_factory()` + модель `Bot`; вставка
  одной строки `bot_slug` (created_at — server default).
- **Rationale**: один и тот же канал настроек и тот же движок, что у
  сервисов (конституция, Configuration: каждый entry point читает
  конфигурацию одинаково); fail-fast без `GRAMMQ_DATABASE_URL` достаётся
  бесплатно. CLI формально не runtime-код, но отдельный синхронный
  двигатель (psycopg) удвоил бы пути к БД.
- **Alternatives**: sync-сессия на psycopg2 — вторая стопка драйверов и
  новый императив конфигурации; отклонено.

## R4. Расположение каталога bots/

- **Decision**: настройка `GRAMMQ_BOTS_DIR` (не секрет) в `Settings`,
  default `./bots` — путь относительно CWD запуска.
- **Rationale**: значение «одно и то же в каждом окружении» по умолчанию
  (категория versioned default конституции); на хостах, где каталог
  отличается, передаётся средой. Тот же канал прочитает воркер доставки
  (фича 003), не вводя второго источника истины.
- **Alternatives**: абсолютный путь-константа — разные хосты; вывод из
  пути env-файла — сущность не та (env-файл вне deploy-дерева).

## R5. Точное правило bot_slug

- **Decision**: `<last4>-<word1>-<word2>`, где `last4` — последние 4 цифры
  числового идентификатора токена, дополненные нулями слева до 4 позиций
  (`42` → `0042`); `word1`, `word2` — два различных слова из встроенного
  Dune-вордлиста (~150 слов, ASCII lower, буквы+дефисы, каждое ≤ 12
  символов); слова выбираются криптографическим ГСЧ (`secrets.choice`),
  ГСЧ инжектируется для тестов. Итог ≤ 4+1+12+1+12 = 30 символов,
  slug-safe ASCII.
- **Rationale**: спека требует 2–3 слова и читаемость; два слова дают
  ~150×149 ≈ 22 тыс. комбинаций на один 4-значный префикс — SC-005 (100
  генераций без дублей) выполняется с запасом; фиксированные два слова
  проще тестировать и читать.
- **Alternatives**: 3 слова — длиннее без нужды; переменное число — хуже
  для контрактных тестов.

## R6. Формат файла `bots/.env-<bot_slug>`

- **Decision**: две строки dotenv-формата:
  `GRAMMQ_BOT_TOKEN={id}:{secret}` и `GRAMMQ_BOT_NAME=<имя>`; файл
  завершается переводом строки. Разбор — минимальный парсер «первый `=`
  делит пару», внешние пробелы значения обрезаются.
- **Rationale**: формат даёт фиче 003 (BotConfig) загрузку файла штатным
  pydantic-settings (`env_file=...`) без собственного парсера на чтение;
  имя на отдельной строке не смешивается с токеном; `=` внутри имени
  безопасен (деление по первому `=`).
- **Alternatives**: JSON — не .env-семантика имени файла; одна строка
  токена — некуда деть имя (FR-003 хранит имя рядом).

## R7. Атомарность создания артефактов (FR-009)

- **Decision**: файл создаётся `os.open(..., O_WRONLY|O_CREAT|O_EXCL,
  0o600)` + `os.fchmod(fd, 0o600)` (права не зависят от umask) + flush/fsync
  до закрытия; затем вставка строки реестра; при любой неудаче/отмене
  после создания файла — компенсирующий `os.unlink`, сессия откатывается.
  Каталог `bots/` создаётся `mkdir(mode=0o700)` до начала ввода токена.
- **Rationale**: O_EXCL закрывает и коллизию имени, и «чужой файл не
  перезаписывается» (Edge Cases); «полуфабрикат» файла длится миллисекунды
  и убирается компенсацией — журнал реестра остаётся источником истины.
- **Alternatives**: temp-файл + `os.replace` — та же атомарность, но
  лишний шаг и мусор в каталоге при сбое между replace и вставкой.

## R8. Контроль дублей токена (FR-012)

- **Decision**: перед созданием артефактов CLI читает все
  `bots/.env-*` (glob), извлекает `GRAMMQ_BOT_TOKEN` и сравнивает полные
  числовые идентификаторы; файлы без валидного токена в сверке не
  участвуют (повреждённый файл = «не готов», не «блокирует регистрацию»).
- **Rationale**: единственный носитель токена — файлы; реестр не
  расширяется (конституция III). Пропуск нечитаемых файлов совпадает с
  задокументированным ограничением контроля дублей в спеке.
- **Alternatives**: отпечаток (hash) идентификатора в реестре — прямо
  запрещено спекой (FR-012).

## R9. Уникальность slug (FR-007)

- **Decision**: кандидат проверяется по двум источникам — отсутствие
  строки в реестре (SELECT по PK) и отсутствие пути `bots/.env-<slug>`
  (любой тип файла: ссылка, каталог — тоже «занято», Edge Cases); при
  занятости — перегенерация, до 50 попыток, затем понятная ошибка.
- **Rationale**: оба источника имени реальны (файл может существовать без
  записи); IntegrityError на вставке (гонка без блокировки FR-013)
  ловится тем же циклом перегенерации.
- **Alternatives**: полагаться только на PK реестра — пропускает
  осиротевшие файлы (Edge Case спеки).

## R10. Прерывание и отмена визарда

- **Decision**: `KeyboardInterrupt` ловится на уровне визарда: артефакты,
  созданные к этому моменту, удаляются, выводится «Регистрация отменена»,
  код возврата 130 (128+SIGINT).
- **Rationale**: FR-009 требует исходного состояния системы при отмене на
  любом шаге; стандартный код 130 сохраняет привычную семантику shell.
- **Alternatives**: не ловить — трейсбек и возможный полуфабрикат файла.

## R11. Владелец каталога и права (FR-014)

- **Decision**: если `bots/` существует — до начала ввода проверяется
  `st_uid == os.geteuid()` и «это каталог»; нарушение — понятная ошибка до
  каких-либо вопросов. Создаваемый каталог получает 0700, файл токена —
  0600 (см. R7).
- **Rationale**: спека требует отказа до начала ввода; права — минимум
  для принципа III (один выделенный пользователь сервисов).
- **Alternatives**: chown-логика — оператор сам создаёт каталог;
  групповой доступ — запрещён спекой.

## R12. Язык интерфейса визарда

- **Decision**: строки для оператора — на русском (рабочий язык проекта);
  идентификаторы, ключи файлов и код — английские.
- **Rationale**: Governance конституции разделяет рабочие языки артефактов
  и кода; CLI-вывод — операционный текст для русскоязычного оператора.
- **Alternatives**: английские строки — не соответствует рабочему языку.
