# Contract: HTTP API (машинный realm)

**Date**: 2026-10-11 | **Spec**: [spec.md](spec.md) | Документ для
разработчика внешнего сервиса.

## Общее

- Base URL: `http://<host>:<port>` (default `127.0.0.1:8080`; GRAMMQ_API_HOST/PORT).
- Авторизация: заголовок `X-API-Key: gmq_...` — на всех маршрутах
  /api/v1/*, кроме /health. Ключ в query или теле не принимается.
- Коды авторизации: 401 `{"detail": "unauthorized"}` — единый ответ для
  отсутствующего, неверного и отозванного ключа (без деталей причины).
- Ключ выдаёт оператор: `gram-mq key add` печатает его один раз.

## POST /api/v1/messages

Запрос:

```http
POST /api/v1/messages HTTP/1.1
X-API-Key: gmq_<43-char-base64url>
Content-Type: application/json

{
  "bot_slug": "6789-arrakis-melange",
  "chat_id": "-1001234567890",
  "text": "Hello from the other service"
}
```

Поля:

| Поле | Тип | Валидация |
|---|---|---|
| bot_slug | string | 1..64 симв.; зарегистрированный бот (иначе 404) |
| chat_id | string | числовой идентификатор чата `^-?\d{1,18}$` ИЛИ `@username` (`^@[A-Za-z0-9_]{4,64}$`) |
| text | string | 1..4096 символов (plain text; parse_mode не поддерживается в MVP) |

Ответы:

| Код | Тело | Смысл |
|---|---|---|
| 202 | `{"id": "<uuid>"}` | принято в очередь; id идентифицирует строку журнала |
| 401 | `{"detail": "unauthorized"}` | нет/неверен/отозван ключ |
| 404 | `{"detail": "bot not found"}` | bot_slug не в реестре |
| 422 | стандартная валидация FastAPI | тело не прошло форматную проверку |
| 5xx | — | инфраструктурный сбой; сообщение НЕ принято, клиент повторяет |

Семантика: 202 не означает доставку — только постановку в очередь.
Доставка at-least-once: при разрыве после отправки в Telegram до
фиксации возможен дубль сообщения в чате (документировано, конституция II).
Идемпотентность постановки в MVP отсутствует: повтор запроса с тем же
телом создаст второе сообщение (dedup-ключ — Future).

## GET /health

Без авторизации. Ответ: 200 `{"status": "ok"}`. Состояние очередей и
конфигурацию не раскрывает.

## Что отсутствует by design (FR-011)

- Эндпоинтов статистики, глубины очереди, управления ключами/ботами по
  HTTP нет; регистрация ботов по HTTP запрещена (фича 002).
- Подсчёт доставленных сообщений — SQL оператором (quickstart.md §5).
