# Contract: `POST /bootstrap/api-key` + настройки активации

**Date**: 2026-10-17 | **Spec**: [spec.md](../spec.md) | Фаза 2
двухэтапной выдачи ключа (US2, US3, FR-005–FR-015).

## Настройки

| Переменная | Тип | Дефолт | Смысл |
|---|---|---|---|
| `GRAMMQ_KEY_BOOTSTRAP_ENABLED` | bool | `false` | включает маршрут активации; читается на старте процесса |
| `GRAMMQ_KEY_BOOTSTRAP_MATERIAL` | SecretStr | не задано | значение активации `prefix:хэш` из вывода [`gram-mq key prepare`](cli-key-prepare.md) |

Обе живут в общем env-канале проекта (конституция Configuration); на PaaS
задаются панелью окружения, применяются редеплоем. Материал — секрет:
`repr()` настроек его не раскрывает, в логи и ответы он не попадает.

## Формат значения активации

```
<prefix>:<key_hash>
```

- ровно один `:`; сплит — по первому вхождению;
- `prefix` — 12 символов, `^gmq_[A-Za-z0-9_-]{8}$`;
- `key_hash` — Argon2id-кодировка, начинается с `$argon2id$`, длина ≤ 128.

Нарушение любого правила — материал считается невалидным (единый отказ,
без различения причин наружу: материал секретен и не эхом).

## Маршрут

```
POST /bootstrap/api-key
```

- Тело: пустое. Заголовки авторизации: не требуются (FR-013) — маршрут
  существует для бутстрапа первого ключа и лежит вне обоих realm-ов
  (`/api/v1/*`, `/api/dashboard/*`).
- Из запроса секреты не приходят вообще: материал читается только из
  `GRAMMQ_KEY_BOOTSTRAP_MATERIAL` (FR-014). Посторонний «пинок» в окно
  активности не даёт входа: plaintext ключа знает только оператор (US3).

## Ответы

| Условие | Код | Тело |
|---|---|---|
| Успех: строка вставлена в `gmq_api_keys` | 201 | `{"status": "activated", "prefix": "<prefix>"}` |
| Prefix уже существует (повторный/конкурентный вызов, включая отозванный) | 409 | `{"detail": "api key already activated"}` |
| Флаг выключен / не задан при сборке | 404 | `{"detail": "not found"}` — маршрут «не существует» |
| Флаг включён, материал не задан или невалиден | 503 | `{"detail": "bootstrap material missing or invalid"}` |

Хэш и материал не возвращаются ни в одном ответе (FR-009); префикс — не
секрет (lookup-идентификатор, и так виден в БД).

## Идемпотентность и конкуренция

- Повторные вызовы с тем же материалом: не более одной строки на материал;
  каждый повтор после первого — 409 (FR-010).
- Конкурентные вызовы: PK по prefix гарантирует ровно одну успешную
  вставку, проигравшие получают 409 (US3 сценарий 2).
- Отказ (404/503/409) ничего не пишет в БД.

## Жизненный цикл ключа после активации

- Активированный ключ немедленно проходит действующую проверку `X-API-Key`
  на `/api/v1/*` (FR-011) — первый же запрос после 201.
- Выключение флага не отзывает ключ: он живёт в `gmq_api_keys` (SC-004);
  отзыв — существующий механизм `revoked_at`, вне скоупа фичи.
- Окно активации закрывается `GRAMMQ_KEY_BOOTSTRAP_ENABLED=false` +
  редеплой; оставлять маршрут включённым после операции не следует
  (повторные вызовы всё равно упираются в 409, но surface держат закрытым).

## Логи

`api key activated prefix=...` (info) · `api key bootstrap conflict
prefix=...` (warning) · `key bootstrap enabled but material missing or
invalid` (error). Без plaintext, хэша и материала (FR-015).
