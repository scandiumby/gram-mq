# Contract: `gram-mq key prepare`

**Date**: 2026-10-17 | **Spec**: [spec.md](../spec.md) | Фаза 1 двухэтапной
выдачи ключа (US1, FR-001–FR-004).

Локальная команда оператора: генерирует ключ и материал активации, ничего
не регистрирует. Полный сценарий активации —
[key-bootstrap-endpoint.md](key-bootstrap-endpoint.md).

## Вызов

```bash
uv run gram-mq key prepare
```

Без флагов и аргументов. Без `GRAMMQ_DATABASE_URL`, без env-файла, без
доступа к сети и БД — команда работает на чистой машине с uv-окружением
проекта (FR-002). `Settings` не инстанцируется.

## Вывод (stdout)

```
API-ключ создан — показывается один раз:
gmq_<43 символа base64url>

prefix: gmq_xxxxxxxx

Значение активации (для GRAMMQ_KEY_BOOTSTRAP_MATERIAL):
gmq_xxxxxxxx:$argon2id$...
```

- plaintext ключ печатается ровно один раз (FR-003, конституция III);
- значение активации — одна строка `prefix:хэш`, готовая к копированию в
  панель окружения деплоя; формат определён в
  [key-bootstrap-endpoint.md](key-bootstrap-endpoint.md);
- ключ, prefix и хэш каждого запуска уникальны (US1 сценарий 3).

## Побочные эффекты

Нет (FR-004): ни записей в БД, ни файлов, ни логов. Единственный носитель
plaintext — терминал оператора.

## Коды выхода

| Код | Смысл |
|---|---|
| 0 | ключ и материал напечатаны |
| ≠0 | внутренняя ошибка (не ожидается: внешних входов нет) |

Отдельных кодов отказа не вводится: у команды нет предусловий, которые
мог бы нарушить оператор.

## Гарантии

- Сгенерированный хэш совместим с действующей верификацией `X-API-Key`
  (тот же Argon2id и формат ключа, что у `key add`) — активированный на
  этапе 2 ключ работает без изменений верификатора (FR-011).
- Существующая команда `gram-mq key add` не меняется (FR-016).
