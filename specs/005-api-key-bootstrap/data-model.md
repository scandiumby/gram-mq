# Data Model: Двухэтапный бутстрап API-ключа

**Date**: 2026-10-17 | **Spec**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md)

## Сущности

### ApiKey — существует (фича 003), не меняется

Записи создаёт эндпоинт активации; схема и миграции — без изменений.

| Поле | Тип | Кто пишет в этой фиче |
|---|---|---|
| prefix | String(12), PK | из значения активации (сгенерирован на этапе 1) |
| key_hash | String(128), NOT NULL | из значения активации (Argon2id, предвычислен на этапе 1) |
| created_at | timestamptz NOT NULL | server_default now() |
| revoked_at | timestamptz NULL | не трогает (отзыв — вне скоупа) |

Открытого ключа в схеме по-прежнему нет (конституция III). Новых таблиц,
колонок и индексов нет.

### Значение активации (переносимый материал, не хранится как сущность)

Одна строка, единица переноса из терминала оператора в настройку сервера:

```
<prefix>:<key_hash>
# пример
gmq_ab12cd34:$argon2id$v=19$m=65536,t=3,p=4$c29tZXNhbHQ$hash...
```

Строится `format_key_material(prefix, key_hash)` на этапе 1, разбирается
`parse_key_material(value)` на этапе 2. Определение формата — [contracts/
key-bootstrap-endpoint.md](contracts/key-bootstrap-endpoint.md).

### Параметры конфигурации (Settings, две новые строки)

| Поле | Тип | Дефолт | Секрет | Смысл |
|---|---|---|---|---|
| key_bootstrap_enabled | bool | `False` | нет | доступность эндпоинта активации |
| key_bootstrap_material | SecretStr \| None | `None` | да | значение активации целиком |

Переменные окружения: `GRAMMQ_KEY_BOOTSTRAP_ENABLED`,
`GRAMMQ_KEY_BOOTSTRAP_MATERIAL`. Читаются на старте процесса; смена
требует применения настроек (редеплой/рестарт).

## Валидации

- **Значение активации** (до любой записи, FR-012): ровно один `:`;
  prefix — `^gmq_[A-Za-z0-9_-]{8}$` (12 символов с `gmq_`); key_hash —
  начинается с `$argon2id$`; длина key_hash ≤ 128 (ширина колонки).
  Нарушение любого правила → `parse_key_material` даёт `None` → эндпоинт
  отвечает 503, ничего не пишет.
- **Ключ этапа 1**: тот же формат, что у `key add` — `gmq_` + 43 символа
  base64url (`secrets.token_urlsafe(32)`); хэш — argon2-cffi с дефолтными
  параметрами. Отдельной «bootstrap-ветки» верификации нет.
- **Уникальность**: повторная активация существующего prefix (включая
  отозванный) — INSERT упирается в PK → 409 без изменения строки; «воскрешение»
  отозванного ключа невозможно (FR-010).

## Жизненный цикл окна активации

```
оператор: uv run gram-mq key prepare
   └─ терминал: plaintext (один раз) + prefix + значение активации
оператор: панель деплоя ← GRAMMQ_KEY_BOOTSTRAP_MATERIAL=<значение>
                         ← GRAMMQ_KEY_BOOTSTRAP_ENABLED=true   (редеплой)
   └─ api-процесс стартует: маршрут активен
оператор: POST /bootstrap/api-key
   ├─ 201 activated (строка prefix+хэш в gmq_api_keys; ключ сразу действует)
   ├─ 409 (prefix уже есть — повторный/конкурентный «пинок»)
   └─ 503 (материал не задан/битый — чинить настройки, не запрос)
оператор: GRAMMQ_KEY_BOOTSTRAP_ENABLED=false   (редеплой)
   └─ маршрут «исчезает» (404); активированный ключ продолжает работать:
      он живёт в БД, а не в настройке (SC-004)
```

Инварианты: plaintext не покидает терминал оператора; по HTTP и в
настройках сервера циркулирует только `prefix:хэш`; в БД — только хэш
(конституция III, SC-003).

## Влияние на другие данные

Нет: журнал сообщений, реестр ботов, файлы `bots/.env-*` не затрагиваются.
Операция активации добавляет ровно одну строку в `gmq_api_keys` и не
изменяет существующие.
